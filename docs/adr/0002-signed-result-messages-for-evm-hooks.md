# EVM Hooks are signed result messages checked by a shared Receiver

To deliver a settled Assertion to an EVM chain, the oracle contract has Chain Signatures sign a result message (chain id, Receiver address, Assertion id, outcome, Claim hash). Any Relayer can send it to one shared Receiver contract per chain, which checks the signer with `ecrecover`, records the outcome once, and calls the consumer. We rejected having the oracle sign full EVM transactions from its derived address: the NEAR contract can't track nonces or see gas prices on the other chain, one stuck transaction blocks every later one, and the derived address would need ETH on every chain. We rejected having each consumer check signatures itself because every consumer would copy security-critical code and need updating if the oracle's address changed. The cost of this choice is a Receiver contract per chain and a Relayer paying gas. NEAR's Omni Bridge uses the same pattern. Research: `docs/research/chain-signatures-hooks.md`.
